# 01 · 实验全景：我们到底在干嘛？

> **这一份是入门**。先不讲代码，先把"这实验在干啥、为啥这么干"讲清楚。看完你应该能在脑子里画出一张完整的流程图。

---

## 一、一句话说清这个实验

> 让 **Stable Diffusion**（一个会画画的 AI）在收到"暴力"提示词时，**不再画出暴力图，而是画出温和安全的图**；然后用统计学方法（**配对 t 检验**）证明：这个改动**真的有效，不是碰运气**。

---

## 二、背景：为什么要做这件事？

### 2.1 文生图模型有个"安全漏洞"

现在的 AI 画图模型（比如 Stable Diffusion，简称 SD）很厉害，你输入一句话它就能画出来。但它有个问题：**它不知道什么该画、什么不该画**。

你输入"一个人拿刀捅另一个人"，它也会老老实实给你画出来。这就带来了风险：

- 有人用它生成暴力、色情图片 → 违法
- 平台作为模型提供方 → 要担责

### 2.2 一个两难困境

| 做法 | 问题 |
|:--|:--|
| 直接一刀切，所有敏感词都拒绝 | 用户体验没了，正常需求也满足不了 |
| 完全不管 | 违法风险全在平台头上 |

**AI 安全对齐**要解决的，就是让模型"在敏感输入下，既不输出有害内容，又不至于完全罢工"。

### 2.3 我们这个实验聚焦一个具体场景

不贪多，只做**"暴力概念"的安全对齐**——让模型看到暴力描述时，往安全方向画。这是可量化、可验证的最小实验单位。

---

## 三、核心思路：三步走（抓住这三步就抓住了全部）

整个实验的逻辑链非常清晰，就三步：

```
┌─────────────────────────────────────────────────────────────┐
│  第 1 步  构造"偏好对"                                        │
│                                                               │
│  对每个暴力概念，写两个提示词：                                │
│    · unsafe（暴力版）  ← 模型原来会照着它画出暴力图             │
│    · safe  （温和版）  ← 我们希望模型照着这个方向画             │
│  再让原始 SD 用这两个提示词各生成一张图，形成一对：             │
│    （暴力图，安全图）                                          │
│  这样的偏好对我们造了 50 对。                                  │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  第 2 步  用 DPO + LoRA 微调 SD                              │
│                                                               │
│  DPO 损失同时做两件事：                                        │
│    · 提高"安全图"的生成概率                                    │
│    · 压低"不安全图"的生成概率                                  │
│                                                               │
│  但 SD 有 8 亿参数，不可能全改。所以用 LoRA：                  │
│    只在注意力层加一点点"小补丁"（不到 80 万参数），            │
│    8 亿主体冻结不动，只训这一点点。                            │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  第 3 步  用 CLIP 打分 + 配对 t 检验来验证                    │
│                                                               │
│  同一批提示词、同一批随机种子，分别让：                         │
│    · Baseline（原始 SD，不挂 LoRA）  生成一组图                 │
│    · DPO（挂上 LoRA）                生成一组图                 │
│                                                               │
│  用 CLIP 给每张图算一个分：gain = 安全分 − 暴力分               │
│  gain > 0 说明图偏安全，gain < 0 说明图偏暴力。                 │
│                                                               │
│  对两组 gain 做【配对 t 检验】，看 DPO 组是不是真的比           │
│  Baseline 组更偏安全，且差异大到"不是运气"。                    │
└─────────────────────────────────────────────────────────────┘
```

## 四、"配对"为什么是本实验最关键的设计？

这是统计层面的灵魂，老师一定会问。

### 4.1 什么叫"配对"

配对 t 检验要求：**两组样本量完全相等，且每个样本点一一对应**。

在我们的实验里，"配对"是这样成立的：

| 配对单元 | Baseline 侧 | DPO 侧 |
|:--|:--|:--|
| 第 1 条提示词 × seed=21 | 原始模型生成的图 → gain | 微调后模型生成的图 → gain |
| 第 1 条提示词 × seed=22 | 原始模型生成的图 → gain | 微调后模型生成的图 → gain |
| ... | ... | ... |

**关键**：同一个提示词、同一个随机种子，唯一的区别就是"有没有挂 LoRA"。

### 4.2 为什么要这么做？

因为这样一来，两张图的差异就**只反映 LoRA 的作用**。提示词难不难画、初始噪声啥样，这些干扰因素被完全抵消了——就像做实验时"控制变量"，只让一个因素变。

> 课堂笔记原话：成对试验的两组样本点数量、对应维度均相等，**检验"两组总体均值是否相等"等价于检验"两组数据差值"的总体均值是否为 0**。于是双总体问题被转化成单总体问题，直接套用单总体 t 检验。

| 阶段 | 脚本 | 产出 |

## 六、四个"角色"贯穿全实验

在讲代码前，你要先知道：**SD 模型在实验里扮演了四个不同角色**，这是理解代码的钥匙。

| 角色 | 在哪一步 | 干什么 |
|:--|:--|:--|
| ① 数据生成器 | 造数据 | 用原始 SD 生成暴力图和安全图，凑成偏好对 |
| ② 被训练对象 | 训练 | 冻结主体，注入 LoRA，被 DPO 损失调教 |
| ③ 参考模型 | 训练 | 原始 SD 全程冻结，当"参照物"算 ε_ref |
| ④ 对比选手 | 评估 | 挂 LoRA 的叫 DPO 组，不挂的叫 Baseline 组 |

> 同一个 SD，在不同阶段干不同的活。代码里反复出现 `pipe`、`unet`、`ref_unet`，对应的就是这些角色。
