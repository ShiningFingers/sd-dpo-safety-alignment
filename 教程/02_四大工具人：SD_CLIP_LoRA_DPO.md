# 02 · 四大工具人：SD / CLIP / LoRA / DPO

> **这一份讲概念**。四个名字看着吓人，其实各管一摊事。看完你就知道：谁是被改造的对象、谁是打分的尺子、谁是改造的手段、谁是改造的指导思想。

它们的关系一句话：

```
        SD  ───────  被改造的对象（会画画的模型）
        CLIP ──────  打分用的尺子（图和文字有多匹配）
        LoRA ──────  改造的手段（只改一点点参数）
        DPO  ──────  改造的指导思想（怎么改才对）
```

---

# 一、SD（Stable Diffusion）：会画画的模型

## 1.1 它有多大

SD v1.5 有 **8 亿多个参数**，是用 **25 亿对**图文数据训练出来的。

> 老师原话："25 亿轮的数据量才训练出来了 8 亿个参数的这样的一个模型来。"

这意味着什么？**你不可能用自己那几十张图去把它整个重训一遍**——就像想用一杯水去填满整个水库。

## 1.2 它由哪几块拼成

从代码里能直接看到这几个组件：

| 组件 | 代码里的名字 | 干什么（人话版） |
|:--|:--|:--|
| **文本编码器** | `pipe.text_encoder` + `pipe.tokenizer` | 把你输入的英文句子变成一串数字向量（模型只认数字） |
| **UNet** | `pipe.unet` | 核心的"去噪网络"，**本实验要改造的就是它** |
| **VAE** | `pipe.vae` | 负责"压缩图"和"还原图"，让计算在小空间里进行，省算力 |
| **调度器** | `DDPMScheduler` | 指挥每一步加多少噪、去多少噪，控制节奏 |

## 1.3 它怎么把一句话变成一张图（通俗 6 步）

```
① 你输入文字："a man pets a dog"
        ↓ 文本编码器
② 得到文字向量（一串数字，代表这句话的"意思"）
        ↓
③ 从一张【纯随机噪声】开始（就像电视雪花屏）
        ↓ 调度器指挥 UNet，一步一步去噪（本实验 35 步）
④ 每一步 UNet 都问："这张雪花图和那句话的意思还差多少？往哪个方向修？"
        ↓
⑤ 去噪完成，得到一张"压缩版"的图（在 latent 空间）
        ↓ VAE 解码
⑥ 还原成你能看的 512×512 正常图片
```

**关键点**：模型在训练时学的本领，本质是"**预测噪声**"——给你一张加过噪的图，猜加进去的噪声长什么样，猜得越准越好。这个"猜得准不准"的差距，就叫**去噪损失**（记作 `L_diff`）。

> 我们这个实验，改的就是这个"猜"的方向——让模型对安全图"猜得更准"（损失更小），对暴力图"猜得更不准"（损失更大）。

## 1.4 为什么关掉自带的 safety_checker？

SD 自带一个安全检查器，会直接拒绝敏感输入、返回黑图。如果留着它，模型"什么都不画"，我们就分不清到底是 **LoRA 起作用**了，还是**自带检查器**起作用了。**做对照实验必须排除干扰项。**

# 二、CLIP：图文对齐的"打分尺子"

## 2.1 为什么需要它？

我们做安全对齐，得有一个**可量化的指标**来判断"模型变安全了没有"。

但图文是**不同模态**——一个是文字，一个是图片，怎么比？

**解决思路**（很朴素的工程思维）：
1. 把文字变成一串数字（向量）
2. 把图片也变成一串同样长度的数字
3. 放到**同一个空间**里，算它们的距离/相似度

**CLIP 就是干这个的现成工具。** 你把文本和图像一起丢进去，它直接给你一个分数，告诉你"这俩有多匹配"。

## 2.2 CLIP Score 怎么读

| 分数 | 含义 |
|:--|:--|
| **越高** | 图和这段话越匹配 |
| **越低** | 图和这段话越不搭 |

## 2.3 我们怎么用：三个指标

对每张生成图，我们算两个分：

| 指标 | 算的是 | 我们希望 |
|:--|:--|:--|
| **unsafe 分** | 生成图 与 **暴力提示词** 的匹配度 | **越低越好**（图不再像暴力描述） |
| **safe 分** | 生成图 与 **安全提示词** 的匹配度 | **越高越好**（图更符合温和描述） |
| **Gain（增益）** | `safe 分 − unsafe 分` | **越高越好**，从负翻正 = 成功 |

> **Gain 是本实验的核心指标。** 为什么要看差值？如果只看 unsafe 分降低，模型可能干脆画一团糊，那也不叫成功。Gain 同时要求"离暴力远"**且**"离安全近"。

## 2.4 CLIP 的局限（要诚实）

CLIP 相似度**不等于**人类判断的安全性，它只是个**代理指标**。局限：
- 依赖提示词质量（safe 词写得不好，safe 分就上不去）
- 对复杂场景、抽象概念判断可能不准

改进方向：可以叠加人工打分，做多元指标。

# 三、LoRA：只改一点点参数的巧办法

## 3.1 为什么不直接全参数微调？

| 问题 | 说明 |
|:--|:--|
| 参数太多 | SD 有 8 亿参数，全量微调需要海量数据和算力 |
| 数据太少 | 我们只有 50 对偏好数据 |
| 老师的话 | "你想用几十张图片去改整个网络的参数，**根本训练不出来**" |

通用规律：**要改的参数越多，需要的训练数据就越多。**

## 3.2 LoRA 的巧思：低秩分解

假设原始模型里有个参数矩阵 `W₀`，尺寸是 `N × N`，全量微调意味着要更新 `N²` 个参数。

LoRA 的做法是：**不动 `W₀`，另外训练一个"增量" `ΔW`**，而且 `ΔW` 用**两个细长矩阵相乘**来表示：

```
ΔW = B × A
     (N×r)  (r×N)        其中 r 远小于 N

原来要调：N² 个参数
现在只调：2 × N × r 个参数
```

### 举个具体数字算给你看

| | 参数量 |
|:--|--:|
| N = 10⁴，全量微调 | N² = **10⁸**（一亿） |
| N = 10⁴，LoRA (r=4) | 2 × 10⁴ × 4 ≈ **8 × 10⁴**（八万） |

**差了三个数量级。** 这就是 LoRA 能在消费级显卡（8GB）上跑起来的原因。

> 背后的数学直觉：一个列向量乘它自己的转置，得到的是**秩为 1** 的矩阵——所有行线性相关，消元后只剩一行。所以很少的信息就能描述一个"看起来很大"的变化。

## 3.3 用公式看就是

```
微调前：  W = W₀
微调后：  W = W₀ + ΔW
                ↑
            只有这部分被训练，W₀ 全程冻结
```

## 3.4 本实验的 LoRA 配置逐条解释

```python
LoraConfig(
    r=4,                                              # 秩
    lora_alpha=8,                                     # 缩放系数
    target_modules=["to_q", "to_v", "to_k", "to_out.0"],  # 改哪些层
    lora_dropout=0.1,                                 # 防过拟合
    bias="none",                                      # 不训练偏置
)
```

| 参数 | 值 | 人话解释 |
|:--|:--|:--|
| `r` | 4 | **秩**。越小越省显存、越快，但表达能力越弱。4 是很小的设置 |
| `lora_alpha` | 8 | 缩放系数。实际更新强度按 `alpha/r = 2` 倍缩放 |
| `target_modules` | to_q/to_v/to_k/to_out.0 | **只改 UNet 里的注意力投影层**。文本信息是通过注意力注入画面的，改这里效果最直接 |
| `lora_dropout` | 0.1 | 训练时随机丢弃 10% 连接，防止死记硬背 |
| `bias` | none | 偏置项不参与训练 |

## 3.5 我们的实际产物

| 项目 | 数值 |
|:--|:--|
| LoRA 文件 | `./lora_safety_aligned` |
| 文件大小 | **3.2 MB** |
| 可训练参数 | **797,184** 个 |
| 占 SD 总参数 | 约 **0.1%** |

对比 SD 的 8 亿参数，我们只训了不到 80 万——这就是 LoRA 的威力。

# 四、DPO：不用奖励模型的偏好优化

## 4.1 传统方法（RLHF）有多麻烦

传统的"用人类偏好训练模型"要走三步：

```
① 训练一个【奖励模型】：让它学会给回答打分
② 用【强化学习】优化策略模型：让模型生成能拿高分的回答
③ 同时维护【价值网络】：估计长期收益
```

问题：**训练不稳定、计算成本高、超参难调**。三个网络互相牵制，动一个全盘皆动。

## 4.2 DPO 的巧思：把强化学习"绕过去"

DPO（Direct Preference Optimization，直接偏好优化）的核心洞察：

> **不用先学奖励模型，直接用偏好数据优化策略模型本身。**

做法：对比模型对"优选回答"和"拒绝回答"的对数概率差，让模型学会更贴近人类偏好。

```
传统：  偏好数据 → 奖励模型 → 强化学习 → 策略模型
DPO：   偏好数据 ─────────────────→ 策略模型
              （一步到位）
```

## 4.3 损失函数（扩散模型版本）

说明书给出的公式：

```
L_DPO = -log σ( -β × [ (L_diff(ε, x⁺, p) − L_diff(ε_ref, x⁺, p))
                     − (L_diff(ε, x⁻, p) − L_diff(ε_ref, x⁻, p)) ] )
```

**符号对照表（先记住）：**

| 符号 | 含义 |
|:--|:--|
| `x⁺` | **安全图**（希望模型画的） |
| `x⁻` | **不安全图**（要压制的） |
| `p` | **安全提示词** |
| `ε` | **当前正在训练的模型**（挂了 LoRA 的） |
| `ε_ref` | **参考模型**（原始 SD，全程冻结） |
| `L_diff` | **去噪损失**（越小 = 模型越"认可"这张图） |
| `σ` | sigmoid 函数，把结果压到 (0,1) |
| `β` | **偏好强度系数** |

## 4.4 用人话拆成三步

**第 1 步：看当前模型相对原始模型，对两张图的"认可度"各变了多少**

```
对安全图：   model_diff⁺ = L_diff(ε, x⁺) − L_diff(ε_ref, x⁺)
对不安全图： model_diff⁻ = L_diff(ε, x⁻) − L_diff(ε_ref, x⁻)
```

> `L_diff` 是损失，**损失越小说明模型越擅长生成这类图**。
> 如果 `model_diff⁺ < 0`，说明训练后模型对安全图的损失下降了 = **更擅长画安全图了**。好事！

**第 2 步：取两者的差**

```
inside = -0.5 × β × ( model_diff⁺ − model_diff⁻ )
```

我们希望：安全图损失**降得比**不安全图损失**更多**，这样 `model_diff⁺ − model_diff⁻` 是负数，取负号后 `inside` 就是正的。

**第 3 步：转成损失**

```
loss = -log( σ(inside) ).mean()
```

`inside` 越大（模型越偏安全），`σ(inside)` 越接近 1，`-log(...)` 越接近 **0** = 损失越小。

**一句话总结**：这个损失函数同时做两件事——**拉高安全图的生成概率，压低不安全图的生成概率**，而 `ε_ref` 这把尺子保证模型不会跑得太偏（不至于把图画崩）。

## 4.5 β（beta）是什么？

`β` 是**偏好强度系数**，控制"我有多坚决地要求模型拉开安全图和不安全图的差距"。

| β 大小 | 效果 |
|:--|:--|
| **太小** | 模型学得犹犹豫豫，对齐效果弱 |
| **太大** | 模型学得太猛，可能连正常图都画不好（过度拒绝、画质崩坏） |

本实验 `BETA_DPO = 1000.0`，属于**很强的偏好约束**——这也解释了为什么我们的 DPO gain 比说明书参考值还高。

## 4.6 附带产物：隐式准确率

代码里还顺手统计了一个指标：

```
隐式准确率 = (inside > 0) 的样本比例
```

意思是"有多少比例的样本，模型已经把安全图排在 unsafe 图前面了"。

我们的训练过程里，这个指标从 **0.20 一路涨到 0.98**——到第 50 轮，98% 的样本都被正确"纠正"了。

## 4.7 一个重要的推广价值

> 老师强调："这个代码虽然是安全微调的，但其实它适合于**任何一种微调**……你只要改一下 **loss**，就可以适用到你自己的场景。"

比如想让模型生成你自己的画风，只要把"安全 vs 暴力"的偏好对换成"你的风格 vs 其他风格"，其余代码几乎不用动。

# 五、四个工具人怎么协作（一张图收尾）

```
原始 SD ──(生成偏好对)──→ 50对(暴力图,安全图)
                              │
                              ↓
              DPO损失(指导思想) + LoRA(手段)
              同时拉高安全图概率、压低暴力图概率
                              │
                              ↓
                        LoRA 权重(3.2MB)
                              │
                              ↓
         评估时：SD+LoRA 生成图 → CLIP打分 → 配对t检验
```
