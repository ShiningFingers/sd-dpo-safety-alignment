# 一、设计精髓：每个选择背后的"为什么"

实验不是随便拼起来的，每个设计都有道理。逐个拆。

## 1.1 为什么用"偏好对"而不是直接给标签？

**传统做法**：给每张图打个"安全/不安全"的标签，训练分类器。

**DPO 的做法**：不给绝对标签，只给"哪个更好"的相对偏好（安全图 > 暴力图）。

**为什么偏好对比标签好？**
- 绝对标签很难标："这张图安全程度打几分？"主观性太强
- 相对偏好容易标："这两张哪张更安全？"人类判断更一致
- DPO 直接利用偏好，不需要先训一个奖励模型来把偏好转成分数

## 1.2 为什么只训 LoRA，不全参数微调？

| | 全参数微调 | LoRA |
|:--|:--|:--|
| 参数量 | 8 亿 | 80 万（0.1%） |
| 需要的数据 | 海量 | 几十对就行 |
| 显存 | 爆 | 8GB 够用 |
| 速度 | 极慢 | ~69 分钟 |

**核心逻辑**：要改的参数越多，需要的数据越多。我们只有 50 对数据，全量微调根本训不动，只会过拟合或训崩。LoRA 用极少量参数就能捕捉到"安全方向"这个变化。

## 1.3 为什么 β 设 1000.0？

β 是偏好强度系数。1000.0 属于**很强的约束**。

**效果**：
- 好处：对齐更彻底，gain 提升更大（我们的结果比说明书参考值还高）
- 风险：β 太大会导致过度拒绝、画质下降（报告 7.2 节讨论了 safe 分下降的副作用）

**这是一个 trade-off**：安全效果 vs 画质保真。我们选了强约束，结果是安全效果很好，但副作用也存在。

## 1.4 为什么评估时要用"中性"negative_prompt？

`test.py` 的 negative_prompt 里含 `violence, blood, weapon, gun, knife, fight, punch, attack` 等词。

**如果评估也用这套**：等于给 Baseline 偷偷加了"防作弊 buff"——负面词本身就会抑制暴力内容，你分不清是 LoRA 起作用还是负面词起作用。

**所以评估脚本换成了中性 negative_prompt**（只保留画质相关词，如 blurry、deformed），保证对比公平。

> 这就是"控制变量"思想：除了"挂不挂 LoRA"这个变量，其他都要一样。

## 1.5 为什么分训练集内和训练集外？

| 数据集 | 回答的问题 | 统计学叫法 |
|:--|:--|:--|
| 训练集内（10 条） | 模型**记住**了吗？ | 拟合能力 |
| 训练集外（30 条） | 模型**泛化**了吗？ | **泛化能力 ← 主结论** |

**只有训练集外也显著，才能说"这个方法真的有用"**，而不是"死记硬背训练题"。这就是为什么报告把训练集外标为"主结论"。

> 类比：考试前你做了 10 道练习题（训练集），考试考了 30 道新题（测试集）。练习题全对不代表你学会了，新题也能做对才说明你真懂了。

## 1.6 为什么用 5 个随机种子？

同一个提示词，不同种子生成的图不一样。用 5 个种子：
- 增加样本量（10 词 × 5 = 50，30 词 × 5 = 150）
- 检验"不同初始噪声下模型能否稳定拒绝暴力"
- 减少单个样本的偶然性

## 1.7 为什么关掉 SD 自带的 safety_checker？

SD 自带一个安全检查器，会直接拒绝敏感输入、返回黑图。

**如果留着**：模型"什么都不画"，你分不清是 **LoRA 起作用**还是**自带检查器**起作用。

**关掉它**：排除干扰项，让 LoRA 的效果纯粹地体现出来。

# 二、踩坑全记录：问题 → 原因 → 解决 → 教训

实验过程中踩了 9 个坑，每个都是真实发生的。这部分最能体现"解决问题的能力"。

## 坑 1：环境没激活（最高频）

**现象**：
```
ModuleNotFoundError: No module named 'torch'
```

**原因**：在 `base` 环境下运行，但 torch 装在 `dpo` 环境里。

**解决**：`conda activate dpo`，确认提示符变成 `(dpo)`。

**教训**：**每次开新终端，第一件事就是 `conda activate dpo`**。

## 坑 2：Windows 路径转义符

**现象**：
```
SyntaxWarning: invalid escape sequence '\D'
```

**原因**：文档字符串里写了 `D:\bigdata_experiment_tangjinping\DPO\`，其中 `\D`、`\b` 被 Python 当成转义符。

**解决**：字符串前加 `r`（raw string）：`r"D:\..."`。

**教训**：Windows 路径在 Python 里一律加 `r` 前缀。

## 坑 3：离线模式 + 模型在本地但加载失败（最绕）

**现象**：
```
OfflineModeIsEnabled
OSError: Cannot load model runwayml/stable-diffusion-v1-5: model is not cached locally
```

**矛盾点**：我们明明验证过模型在本地缓存里！

**因果链**：
```
① 脚本设了 HF_HUB_OFFLINE=1（强制离线）
② 但环境里 HF_ENDPOINT 指向镜像站
③ diffusers 加载 pipeline 时，会先联网查元数据
④ 离线模式禁止联网 → 查元数据失败
⑤ diffusers 判定 "model is not cached locally" → 报错
```

**关键对比**：同一时刻 CLIP 却加载成功了。因为 CLIP 用 transformers 的单模型加载，不走 pipeline 那套元数据预检。

**解决**：绕过 repo id，直接写本地绝对路径：
```python
BASE_MODEL = r"C:\Users\liuhaoyu\.cache\huggingface\hub\models--runwayml--stable-diffusion-v1-5\snapshots\451f4fe16113bff5a5d2269ed5ad43b0592e9a14"
```

**教训**：`HF_HUB_OFFLINE=1` 不是万能的。想强制离线，最可靠的是**直接给本地路径**。

## 坑 4：DEBUG 没关，样本量只有十分之一（最危险）

**现象**：标题写着 `n=50 / n=150`，但实际打印 `n=10`、`df=9`。

**原因**：
1. `DEBUG=True` 只取前 2 个词 → 2×5=10
2. 标题里的 `(n=50)` 是写死的文字

**危险**：如果只看标题，会把 n=10 的结果写进报告——老师一看 df=9 就知道没跑全。

**解决**：
```python
DEBUG = False
# 标题改成动态显示
paired_ttest(b_in, d_in, f"训练集内 (实际n={len(b_in)}, DEBUG={DEBUG})")
```

**验收标准**：看到 `df=49` 和 `df=149` 才算真跑完。

**教训**：**标题里的数字一定要动态计算，不能写死。**

## 坑 5：置信区间两个数打架

**现象**：同一个实验，`eval_dpo.py` 输出的 95%CI 和 `plot_results.py` 画的图上的 CI 不一样。

| 来源 | 训练集内 95%CI |
|:--|:--|
| `eval_dpo.py` | [+9.0412, +12.0170] |
| `plot_results.py` | [+9.0779, +11.9803] |

**原因**：算 CI 时乘的临界值不同。

| 脚本 | 临界值 | 说明 |
|:--|--:|:--|
| `eval_dpo.py` | `t.ppf(0.975, 49)` ≈ 2.0096 | t 分布 |
| `plot_results.py` | 1.96 | 正态近似（z 值） |

**解决**：统一改成 `stats.t.ppf(0.975, n-1)`。

**教训**：配对 t 检验用的是 t 分布，CI 就该用 t 临界值，不能偷懒用 1.96。

## 坑 6：不知道 `it/s` 是什么

**解答**：`it/s` = iterations per second = 每秒迭代次数。在 SD 里，一次迭代 = UNet 走一个去噪步。

```
35/35 [00:11<00:00, 3.16it/s]
 ↑     ↑            ↑
 35步  耗时11秒     每秒3.16步
```

3.1 it/s ≈ 一张图 35 步 ≈ 11 秒。

## 坑 7：拔电源后速度从 3.1 掉到 2.9

**原因**：笔记本 GPU 在电池模式下被电源管理压性能（功耗墙下调、CPU 降频）。

**教训**：跑长实验**插着电源**，速度更稳更快。

## 坑 8：图上有星号 `***`

**解答**：显著性标记。p<0.001 显示三颗星。我们的 p 是 10⁻¹⁹ 和 10⁻³⁰，所以是最高档。

## 坑 9：箱线图上有空心圆圈

**解答**：matplotlib 自动标的**异常值**（落在 Q1−1.5×IQR 以下或 Q3+1.5×IQR 以上的点）。

我们图上两组圆圈：
- 训练集内 Baseline 下方 3 个：原始模型在某些提示词上生成极度暴力的图 → **这正是做安全对齐的动机**
- 训练集外 DPO 下方 3 个：对齐后仍有 ~2% 失败样本 → **写进局限性，显得分析诚实**

**教训**：异常值不是 bug，是可写进报告的分析素材。

# 三、改进方向：实验还能怎么提升？

报告里已经写了 6 条不足与改进，这里按"投入产出比"排序。

## 3.1 补充消融中间轮次（最容易做，已具备条件）

**现状**：只测了 epoch_10/30/50，epoch_30 vs 50 的差异未通过 Bonferroni 校正。

**改进**：补充 epoch_20、epoch_40，提高曲线分辨率，确认"先升后降"的趋势。

**条件**：10 个 checkpoint 都在，直接跑就行，每个约 25 分钟。

## 3.2 做 β 的消融实验（中等投入）

**现状**：β 固定 1000.0，不知道其他值效果如何。

**改进**：跑 β = 200 / 500 / 1000 / 2000，找安全效果与画质保真的平衡点。

**价值**：直接回应"β 怎么选"这个核心超参问题，体现对 DPO 的深入理解。

## 3.3 扩大概念覆盖（高投入，高价值）

**现状**：只用了"暴力"一个概念，标准 AlignGuard 用 723 个概念、7 个类别。

**改进**：扩展到性、仇恨、自残等更多类别。

**价值**：结论的推广性大大增强。但需要更多数据和训练时间。

## 3.4 增加人工评估（中等投入）

**现状**：只用 CLIP 自动打分。

**改进**：叠加人类盲评，与 CLIP 构成二维指标（CLIP 值 + 人工分），做多元均值向量检验。

**价值**：CLIP 是代理指标，人工评估更接近真实安全性。老师课上也提到过这个拓展方向。

## 3.5 刻画副作用（低投入，已具备数据）

**现状**：报告提到 safe 分下降（相关性下降），但没有系统量化。

**改进**：引入语义保真度指标（如 CLIP 图文相似度本身）、FID 画质指标，对副作用做定量刻画。

**价值**：让"不足"部分更有数据支撑，不是空口说白话。

## 3.6 针对长尾失效样本分析（低投入）

**现状**：知道有 3 个失败样本，但没分析为什么失败。

**改进**：把那 3 个样本的提示词和生成图拎出来，分析是提示词问题还是概念本身难对齐。

**价值**：体现"发现问题→分析问题"的能力。

# 四、可迁移性：这套代码怎么用到自己的场景？

老师特别强调过：这个代码框架适合**任何一种偏好微调**，只要改 loss 和数据。

## 4.1 迁移步骤

假设你想让模型生成"你自己的画风"：

| 步骤 | 改什么 |
|:--|:--|
| 1. 改偏好对 | 把"暴力/安全"换成"你的画风/其他画风" |
| 2. 改提示词列表 | `UNSAFE_PROMPTS` → 其他画风，`SAFE_PROMPTS` → 你的画风 |
| 3. 重新生成数据 | `prepare_preference_data()` 重新跑 |
| 4. 训练 | `mini_train.py` 不变 |
| 5. 评估 | `eval_dpo.py` 的提示词换成你要测的 |

**核心代码（DPO 损失、LoRA 配置、训练循环）几乎不用动。**

## 4.2 更一般的迁移

DPO 的本质是"**用偏好对优化模型**"。只要你能定义"什么是好、什么是坏"，就能用：

| 场景 | 偏好对定义 |
|:--|:--|
| 画风迁移 | 你的画风 > 其他画风 |
| 风格化 | 水彩风 > 写实风 |
| 内容安全 | 安全图 > 暴力图 |
| 画质提升 | 高清图 > 模糊图 |

# 五、上台讲解的建议结构（5 分钟版）

如果要答辩，按这个结构讲最稳：

1. **我们要解决什么问题**（30 秒）
   - AI 文生图有安全风险，暴力内容治理
   - 两难：不能一刀切，也不能不管

2. **方法**（90 秒）
   - 三步走流程图（偏好对 → DPO+LoRA → CLIP+配对t检验）
   - 强调"配对"的统计意义

3. **怎么证明有效**（90 秒）
   - CLIP Gain 指标（safe − unsafe）
   - 配对设计：同提示词同种子，只变"挂不挂 LoRA"
   - 配 fig3 配对斜率图

4. **结果**（60 秒）
   - 读四个数：Δ、t、p、Cohen's d（集外为主结论）
   - 配 fig1 柱状图
   - 一句话：p≪0.05，d>0.8，集外也显著 → 泛化成立

5. **不足与改进**（30 秒）
   - 单概念、长尾失效、CLIP 局限、β 副作用
   - 可选：消融发现 epoch_30 最优

# 六、一句话总结这个实验的精髓

> **用最少的参数（LoRA）、最直接的偏好信号（DPO）、最严谨的统计验证（配对 t 检验），在消费级显卡上证明了"文生图安全对齐"是可行的，而且能泛化到没见过的概念。**

这个实验的精髓不在于用了多复杂的技术，而在于**用简单的方法回答了一个明确的问题，并且用统计方法严谨地证明了答案**。
